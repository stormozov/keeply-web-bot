
# Keeply web bot

[![CI Pipeline](https://github.com/stormozov/keeply-web-bot/actions/workflows/ci.yml/badge.svg)](https://github.com/stormozov/keeply-web-bot/actions/workflows/ci.yml)

Клиентская часть веб-бота для организации информации в формате чата. Персональный цифровой ассистент для хранения, поиска и управления информацией

## 🧠 Концепция
В эпоху цифрового шума мы всё чаще теряем важную информацию в потоках чатов, заметок и файлов. Keeply Web Bot — это попытка создать прототип бота-органайзера, который работает как ваш личный архив, помощник и центр управления данными.

Вдохновлённый интерфейсами Telegram, Slack и WhatsApp, Keeply не требует собеседника: вы общаетесь с системой напрямую. Просто отправьте текст, ссылку, изображение, видео или команду — и бот сохранит, структурирует и поможет найти это позже.

> **Цель:** превратить хаотичный поток информации в упорядоченное, легко доступное и функциональное хранилище. 

## Демо

Прототип бота доступен на Github Pages - https://stormozov.github.io/keeply-web-bot/

> [!IMPORTANT]
> ВАЖНО. Сервер на Render имеет ограничения, если сервер не будет получать запросы. Поэтому могут быть задержки в запросах на 50 секунд. Также Render сам очищает чат при долгом простое. Важно, что демонстрация работы бота предоставляет прототип, а не полноценное приложение для общего использования.

## ✨ Ключевые возможности

### Основной функционал

- 📝 Сохранение текстовых сообщений с интегрированной поддержкой гиперссылок ([плагин linkify](https://linkify.js.org/)), обеспечивающей их распознавание и возможность интерактивного взаимодействия.
- 🖼️ Загрузка мультимедийных файлов, таких как изображения, аудио и видео, может быть осуществлена посредством интуитивно понятного интерфейса Drag & Drop или посредством активации специализированной кнопки.
- ⬇️ Скачивание вложений на устройство пользователя может происходить двумя способами. Первый — загрузка отдельного файла. Второй — получение всех вложений из выбранного сообщения в виде структурированного ZIP-архива с разделением файлов по типам.
- 📜 Механизм ленивой загрузки чата, при котором осуществляется асинхронное получение данных, обеспечивает динамическое обновление содержимого интерфейса в реальном времени. В частности, при достижении верхней границы видимой области экрана инициируется запрос на сервер, в результате которого происходит загрузка следующей порции данных, включающей в себя десять последних сообщений. Данный подход позволяет оптимизировать использование сетевых ресурсов и улучшить пользовательский опыт, обеспечивая непрерывное отображение актуальной информации без необходимости полной перезагрузки страницы.

### Дополнительный функционал

- 📌 Закрепление одного сообщения — отображается в верхней части чата. За основу взят функционал Telegram. При клике на полосу закрепленного сообщения страница плавно прокручивается к нему. Если сообщение еще не загружено, бот автоматически подгружает новые порции сообщений. Если нужное сообщение найдено, происходит плавная прокрутка. Если после 100 попыток сообщение не найдено, появляется уведомление. Это сделано для защиты от случайных ошибок, загрузки пустых порций и действий злоумышленников. В будущем можно улучшить функционал, чтобы вместо ошибки показывать закрепленное сообщение другим способом, например, в модальном окне.
- 🎵 Воспроизведение аудио- и видеофайлов, отправленных пользователями, прямо в чате с помощью нативных HTML5-элементов `<audio>` и `<video>`.
- 📚 Архивирование файлов в `ZIP-архив` для скачивания всех вложений одного сообщения.
- 🤖 Поддержка оформления сообщения от бота
- 🤖 Команда `help`, которая отправляет заранее заготовленный пост о возможностях бота и его ограничениях. Данный ответ хранится в формате `markdown` на сервере, там же он преобразуется в html строку для рендеринга на стороне клиента.
- ⚙ Сайдбар для настроек бота с вложенным меню.
- 🧹 Кнопка очистки чата. При нажатии на неё чат полностью очищается. С сервера удаляются все сообщения и файлы.
- 🔔 Менеджер уведомлений. Основные действия пользователя, такие как отправка сообщения, прикрепление вложения или ошибка при его добавлении, сопровождаются всплывающими уведомлениями. Эти уведомления бывают четырех типов: успех, ошибка, информация и предупреждение. Их можно настроить по положению: сверху-слева, сверху-справа или по центру снизу.
- 📃 Визуальная и логическая сортировка прикрепленных файлов в сообщении. Каждый тип файлов (изображения, видео, аудио) отображаются в своей отдельной секции.
- ➕ Выпадающее меню с возможными действиями с выбранным сообщением. Возможные действия: удалить, закрепить, скачать вложения. Кнопка "Скачать вложения" будет доступна только при наличии вложений в сообщении.
- 👉 Всплывающие подсказки в пользовательском интерфейсе (UI), целью которых является повышение когнитивной доступности и улучшения понимания функциональности интерактивных элементов. Например, если строка поиска недоступна, это состояние дополняется подсказкой при наведении.
- 🖼 Лайтбокс для изображений, реализованный с помощью библиотеки [SimpleLightbox](https://simplelightbox.js.org/). У каждого сообщения свой лайтбокс.
- 👇 Кнопка для возврата к началу сообщений при скролле вверх.
## 👩‍💻 Технический стек

**Фронтенд:** 

- Менеджер пакетов [Yarn](https://www.npmjs.com/package/yarn)
- Написана полностью на TypeScript
- SCSS
- Сборка через Webpack с поддержкой code splitting
- Транспиляция через Babel, линтинг через ESLint
- Модульная архитектура: компоненты, сервисы, утилиты и менеджеры состояний разделены по ответственности
- [Плагин linkify](https://linkify.js.org/) для создания гиперссылок из пользовательского ввода текста

- [Axios](https://www.npmjs.com/package/axios) для показа прогресса отправки сообщений
- [Material Symbols & Icons](https://fonts.google.com/icons) - для отображения иконок

**Бэкенд:**

- Koa.js ([подробнее тут](https://github.com/stormozov/keeply-web-bot-back))
- Серверная часть выложена на [Render](https://render.com/)

## 🔐 Переменные окружения (Environment Variables)

Чтобы запустить этот проект, вам нужно добавить следующие переменные среды в файл .env

`DEV_PORT` - Порт для webpack разработки

`SERVER_URL` - Основной адрес сервера

`BACKUP_SERVER_URL` - Резервный адрес сервера (например, для локального сервера)

## Локальный запуск

Склонируйте репозиторий локально

```bash
  git clone https://github.com/stormozov/keeply-web-bot.git
```

Установите зависимости

```bash
  yarn install
```

Запустите сервер разработки

```bash
  yarn run dev
```

## API Reference

#### Получить настройки доступности бота

```http
  GET /api/capabilities
```

Возвращает поддерживаемые ботом функции и возможности. 

---

#### Получить сообщения (с разбивкой по страницам)

```http
  GET /api/messages?offset=${offset}&limit=${limit}
```

| Параметр | Тип     | Описание                       |
| :-------- | :------- | :-------------------------------- |
| `offset`      | `number` | Количество сообщений, которые нужно пропустить. По умолчанию: `0` |
| `limit`      | `number` | Максимальное количество сообщений для загрузки. По умолчанию: `10` |

Ответ:
- ✔ При успехе. Объект с двумя полями: `success` (Boolean) и `data` ([IUserMessageCard](https://github.com/stormozov/keeply-web-bot/blob/main/src/ts/KeeplyBot/shared/interfaces.ts#L71))
- ❌ При ошибке. Объект с двумя полями: `success` (Boolean) и `error` (string)

---

#### Отправить сообщение

```http
  POST /api/messages
```

| Параметр | Тип     | Описание                       |
| :-------- | :------- | :-------------------------------- |
| `message`      | `string` | **Обязательно** Текст сообщения пользователя. |
| `files`      | `file[]` | Список файлов для прикрепления. Необязательно. |

Ответ:
- ✔ При успехе. Объект с двумя полями: `success` (Boolean) и `data` ([IUserMessageCard](https://github.com/stormozov/keeply-web-bot/blob/main/src/ts/KeeplyBot/shared/interfaces.ts#L71))
- ❌ При ошибке. Объект с двумя полями: `success` (Boolean) и `error` (string)

> Примечание: Используется [axios](https://www.npmjs.com/package/axios) с поддержкой отслеживания прогресса загрузки. 

---

#### Удалить сообщение

```http
  DELETE /api/messages/${messageId}
```

Удаляет сообщение с указанным идентификатором. 

| Параметр | Тип     | Описание                       |
| :-------- | :------- | :-------------------------------- |
| `messageId`      | `string` | **Обязательно** Уникальный ID сообщения. |

Ответ:
- ✔ При успехе. Объект с двумя полями: `success` (Boolean) и `message` (string)
- ❌ При ошибке. Объект с двумя полями: `success` (Boolean) и `error` (string)

---

#### Удалить все сообщения


Ответ:

- ❌ При ошибке. Объект с двумя полями: `success` (Boolean) и `error` (string)
